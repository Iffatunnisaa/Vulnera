# VULNERA - WORKFLOW DAN ALUR PROSES SISTEM DETEKSI KERENTANAN

## 📋 OVERVIEW SISTEM
Vulnera adalah sistem deteksi kerentanan berbasis machine learning yang menganalisis traffic jaringan untuk mengidentifikasi serangan cyber. Sistem menggunakan model hybrid BERT-TensorFlow untuk deteksi anomali dan klasifikasi serangan.

## 🏗️ ARSITEKTUR SISTEM

### Komponen Utama:
1. **Web Application (Node.js/Express.js)** - Port 3000
2. **ML Backend (Python/FastAPI)** - Port 8000
3. **Database (MongoDB)** - Port 27017
4. **AI Integration (Gemini API)** - External

## 🔄 ALUR PROSES LENGKAP

### 1. INISIALISASI SISTEM

#### 1.1 Startup Web Application
```
app.js → config/index.js → load all configurations
├── server.js (port, session, CORS)
├── database.js (MongoDB connection)
├── security.js (file upload, security headers)
├── mlBackend.js (ML service configuration)
└── multer.js (file upload middleware)
```

#### 1.2 Database Connection
```
utils/db.js → mongoose.connect() → MongoDB
├── Users collection (authentication)
└── Dataset collection (CSV analysis results)
```

#### 1.3 ML Backend Startup
```
ml-service/backend/app.py → FastAPI server
├── Load BERT tokenizer
├── Load TensorFlow model
├── Load scaler & encoder
└── Start prediction endpoints
```

### 2. SISTEM AUTENTIKASI

#### 2.1 User Registration Flow
```
GET /register → register.ejs
POST /register → authController.register()
├── Validate input data
├── Check email uniqueness
├── Hash password (bcrypt)
├── Save to Users collection
└── Redirect to /login
```

#### 2.2 User Login Flow
```
GET /login → login.ejs
POST /login → authController.login()
├── Check admin credentials (admin@gmail.com)
├── OR validate user credentials
├── Compare password (bcrypt)
├── Create session
└── Redirect based on role:
    ├── Admin → /admin/home
    └── User → /homepage
```

#### 2.3 Session Management
```
express-session middleware
├── Store user data in session
├── Set authentication flags
├── Handle session cookies
└── Middleware protection (isAuth, isAdmin)
```

### 3. UPLOAD DAN ANALISIS CSV

#### 3.1 File Upload Process
```
GET /admin/uploadcsv → uploadcsv.ejs
POST /admin/upload → uploadController.uploadCSV()
├── Multer middleware validation
├── File type & size validation
├── Save to public/uploads/
└── Proceed to ML processing
```

#### 3.2 ML Backend Processing
```
uploadController.sendToMLBackend()
├── Read CSV file
├── Create FormData
├── POST to ML Backend (/predict-csv/)
└── ML Backend Processing:
    ├── Load CSV with pandas
    ├── Feature extraction
    ├── BERT tokenization
    ├── Model prediction
    └── Return predicted CSV
```

#### 3.3 Feature Engineering (ML Backend)
```
extract_features() function:
├── Port categorization (well-known, registered, dynamic)
├── Bot detection from User-Agent
├── Suspicious pattern detection
├── Browser type classification
├── URL security analysis
├── File extension categorization
├── HTTP status code analysis
└── URL depth & parameter counting
```

#### 3.4 Model Prediction
```
Hybrid BERT-TensorFlow Model:
├── Text features → BERT tokenizer
├── Categorical features → Target encoder
├── Numeric features → Scaler
├── Multi-modal input processing
├── TensorFlow model inference
└── Output: predicted_label
```

#### 3.5 Data Storage
```
uploadController.readPredictedCSV()
├── Parse predicted CSV results
├── Save to MongoDB Dataset collection
├── Cleanup temporary files
└── Flash success message
```

## 🔧 TROUBLESHOOTING COMMON ISSUES

### Database Issues
- Check MongoDB connection string
- Verify database service is running
- Check collection permissions

### ML Backend Issues
- Verify FastAPI service on port 8000
- Check model files in artifacts/
- Verify tokenizer configuration
- Check TensorFlow model loading

### File Upload Issues
- Check upload directory permissions
- Verify file size limits
- Check MIME type validation
- Ensure temporary file cleanup

### Authentication Issues
- Check session configuration
- Verify password hashing
- Check role-based access
- Validate session timeout
